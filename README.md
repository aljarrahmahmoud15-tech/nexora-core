# NEXORA Core

النواة المستقلة لمركز NEXORA: قاعدة بيانات خاصة، قواعد يلتزم بها كل بوت، ومسارات (Modules) تُضاف أو تُعطَّل دون المساس بالباقي. المالك هو صاحب القرار، وNEXORA تنفّذ وتسجّل.

## النشر على Render
1. ارفع هذا المجلد إلى ريبو GitHub جديد (مثلاً `nexora-core`).
2. أنشئ **PostgreSQL** وخدمة **Web Service** من الريبو (Build: `npm install`، Start: `npm start`)، في المنطقة نفسها.
3. في Environment للخدمة: `DATABASE_URL` (الرابط الداخلي)، و`PGSSL=false`، و`OWNER_TOKEN` (32 حرفاً عشوائياً أو أكثر تكتبه أنت في لوحة Render ولا ترسله لأحد).
4. الجداول تُنشأ تلقائياً عند أول تشغيل. لا تحتاج Shell.
5. افتح الموقع، واضغط «دخول المالك»، ومن تبويب البوتات أصدر رمزاً لكل بوت (يظهر مرة واحدة).
6. اختبر: `curl https://<خدمتك>.onrender.com/api/telemetry` يجب أن يرجع JSON.

> لا ترسل أي رمز في المحادثات أو تضعه في الكود.

## المسارات
| المسار | الوصول | الوظيفة |
|---|---|---|
| `GET /health` | عام | فحص الحياة |
| `GET /api/telemetry` | عام (أرقام وحالات فقط) | يقرأه المركز كل 15 ثانية |
| `POST /api/m/bots/heartbeat` | بوت | يبلّغ حالة واتساب |
| `GET /api/m/bots/me` | بوت | يعرف رابط القروب الذي يجب الانضمام إليه |
| `PUT /api/m/bots/:id/group` | مالك | إضافة رابط الدعوة = تفعيل القروب |
| `POST /api/m/captains/join` | بوت | تسجيل كابتن، والسعة (250) تفرضها NEXORA |
| `POST /api/m/approvals` | بوت | طلب إجراء حساس (تسوية، استرداد، خصم) |
| `POST /api/m/approvals/:id/decide` | مالك | موافقة أو رفض صريح |
| `POST /api/m/settlements/can-accept` | بوت | هل يُسمح للمنفذ بقبول الطلب؟ (حد المديونية 2 دينار) |
| `POST /api/m/settlements/shadow` | بوت | تسجيل التسوية التي كانت ستنفذها NEXORA (ظل، لا تحرك أي رصيد) |
| `GET /api/m/settlements/shadow` | مالك | مجاميع الظل لمقارنتها بـV26 |
| `GET/PUT /api/owner/rules` | مالك | القواعد التي تلتزم بها كل البوتات |
| `PUT /api/owner/modules/:name` | مالك | تفعيل/تعطيل مسار |
| `GET /api/owner/audit` | مالك | سجل التدقيق |

الترويسات: المالك `Authorization: Bearer <OWNER_TOKEN>`. البوت `Authorization: Bearer <رمز البوت>` و`X-Bot-Id: b1`.

## إضافة مسار جديد
أنشئ ملفاً في `src/modules/` يصدّر `name` و`version` و`register(router, ctx)`. يُحمَّل تلقائياً، ويمكن تعطيله دون إعادة نشر. المسار المقترح ذاتياً (`approvals` بنوع `new_module`) لا يُنشر قبل موافقتك.

## منطق التسوية
المنفذ يقبض الأجرة كاملة نقداً، فيُخصم 15% من محفظته. تصير حصة المنزل (صاحب العرض)، والشركة تأخذ 15% منها، والمنزل يستلم الصافي. كل المبالغ بالفلس وأعداد صحيحة، والمجموع دائماً صفر. `npm test` يتحقق من ذلك على كل سعر حتى 50 ديناراً.

## NEXORA هي الأساس وصاحبة القرار
البوت مجرد عين ويد: يرسل ما رآه في القروب إلى `POST /api/m/engine/event` ثم ينفّذ الرد الذي تعيده NEXORA. القرار كله هنا: تسجيل العرض، قبول الطلب، فحص حد المديونية، تثبيت الحجز، وتنفيذ التسوية في دفتر قيود لا يُعدَّل، مرة واحدة لكل حجز.

شكل الحدث:
```json
{ "type": "message", "msgId": "...", "senderPhone": "9627...", "text": "...", "quotedMsgId": "..." }
{ "type": "reaction", "targetMsgId": "...", "senderPhone": "9627...", "emoji": "👍" }
```
على البوت أن يرسل رقم المرسل الحقيقي (`senderPhone`)، وأن يحلّ معرّفات @lid إلى رقم قبل الإرسال.

**مفتاح السلطة:** لكل بوت حقل `authority` (`v26` أو `nexora`). لا يقبل المحرك أحداثاً من بوت سلطته `v26`، فلا تُسوّى مجموعة مرتين. غيّره بـ `PUT /api/m/bots/:id/authority` بعد إيقاف التسوية في V26 لذلك القروب. أما البوتات 2 إلى 5 فجديدة، فتبدأ بسلطة `nexora` من اليوم الأول.

| المسار | الوصول | الوظيفة |
|---|---|---|
| `POST /api/m/engine/event` | بوت | الحدث ← القرار والتسوية |
| `GET /api/m/engine/bookings` | مالك | الحجوزات |
| `GET /api/m/wallets` | مالك | الأرصدة (`?negative=1` للمديونين) |
| `GET /api/m/wallets/ledger?captainId=` | مالك | قيود كابتن |
| `POST /api/m/wallets/adjust` | مالك | شحن أو تصحيح رصيد (قيد جديد دائماً) |

## الموقع
بعد النشر على Render يعمل موقع واحد:
- `https://<خدمتك>.onrender.com/` لوحة المركز. الأرقام عامة وتُقرأ تلقائياً من `/api/telemetry` كل 15 ثانية. وبعد «دخول المالك» تظهر روابط القروبات وتُعدَّل، ويظهر سجل التدقيق.
- `https://<خدمتك>.onrender.com/admin/` لوحة الإدارة.

الواجهة العامة لا تعرض روابط القروبات ولا أرقام الهواتف. للتأكد ممّا تكشفه: افتح `/api/telemetry` وراجع الحقول.

### تثبيته كتطبيق مستقل
افتح الموقع في Chrome على الهاتف، ثم القائمة ⋮ ثم «تثبيت التطبيق» (أو «إضافة إلى الشاشة الرئيسية»). يظهر بأيقونته ويفتح بملء الشاشة دون شريط المتصفح. الخدمة لا تحفظ أي بيانات مؤقتاً، فالأرقام تأتي حية دائماً.

## لوحة إدارة NEXORA
تُخدَّم من الخادم نفسه على `/admin` بدل V26 للبوتات التي سلطتها `nexora`. تفتحها بـ `OWNER_TOKEN` (يبقى في ذاكرة الصفحة فقط ويُمحى بعد 15 دقيقة خمولاً).
- **حجز جديد:** رقم المنزل + رقم المنفذ + السعر، مع معاينة التسوية قبل التنفيذ، وخيار التثبيت المباشر.
- **الحجوزات:** تأكيد حجز معروض أو إلغاؤه.
- **الأرصدة:** المدينون، وتسوية رصيد (شحن أو تصحيح) كقيد جديد.
- **البطاقات:** إصدار بطاقات `FD-5JD-XXXX-XXXX` (تظهر الأكواد مرة واحدة) وإلغاء الفعّال منها.
- **التدقيق:** سجل كل ما جرى.

استبدال البطاقة: `POST /api/m/cards/redeem` من البوت بـ `{ "phone": "...", "code": "..." }`. الكود صالح لمرة واحدة، وبعد 5 محاولات خاطئة يُقفل الكابتن 15 دقيقة.

## وضع الظل
الوحدة `settlements` لا تحرّك رصيداً. تسجّل ما كانت ستسوّيه، وتقارن مجاميعها بـV26. وبعد تطابق كافٍ يُقرَّر نقل السلطة.
